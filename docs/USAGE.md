# 使用指南

本文面向已启动爱签网关（ai-sign-in-gateway）的使用者，说明如何登录、添加站点、执行签到、配置聚合网关和排查常见问题。部署上线请看 [部署指南](DEPLOYMENT.md)。

## 登录与初始化

打开服务地址，例如：

```text
http://127.0.0.1:3721   # 开发脚本前端
http://127.0.0.1:8972   # 生产服务或 Docker
```

默认管理员：

- 用户名：`admin`
- 密码：`admin123`

首次登录后建议立即完成：

1. 进入 `设置 -> 账号与密码`，修改用户名和密码。
2. 进入 `网关中心 -> 网关策略`，设置网关 API Key。
3. 按需要调整签到时间、请求超时、并发和重试次数。

## 页面概览

- `总览`：查看站点总量、可用状态、余额汇总、最近签到和异常站点。
- `站点中心`：维护站点、分组、插件配置、连通测试、签到、余额探测、API Key 和邀请码。
- `网关中心`：查看网关概览、实时调用、时间段消耗、路由池、策略配置、路由历史和最近请求。
- `验证与对话`：选择站点后自动读取模型列表，用所选模型做对话、参考图输入或图片生成验证。
- `设置`：管理员账号、签到计划、网关策略等系统设置。

## 站点管理

进入 `站点中心`，点击 `新增站点`。

### 基础信息

常用字段：

- `名称`：便于识别的站点名。
- `站点地址`：站点首页或 API 根地址。
- `插件`：决定登录、签到、余额、API Key 同步方式。
- `分组`：可多选，用于站点筛选和网关按组路由。
- `启用`：停用后不参与签到和网关路由。

站点列表中的站点名称旁有新标签页打开图标，可直接打开站点。

### 插件类型

| 插件 | 用途 |
|---|---|
| `http-relay-station` | 通用 HTTP 站点，适合自定义登录/状态/签到接口 |
| `api-supplier` | 仅作为网关供应商记录，不登录、不签到 |
| `sub2api-platform` | 适配 sub2api 类站点，支持 token 或账号密码登录、签到、API Key 同步 |
| `yellowpeach-newapi` | 适配 NewAPI 类站点，支持 cookie/token/账号密码、签到、API Key 同步 |

### 凭证与配置

不同插件会显示不同字段。常见字段：

- `api_key`：用于模型请求的 Key。
- `api_keys`：同步得到的多 Key 列表，网关会展开成多条路由。
- `access_token` / `refresh_token` / `cookie`：用于站内登录或状态接口。
- `username` / `email` / `password`：用于自动登录。
- `totp_secret` / `totp_otpauth_url`：二次验证，系统会自动生成当前验证码。
- `gateway_request_url(s)` / `api_request_urls`：上游模型请求地址，支持多个出口按顺序回退。
- `gateway_priority` / `gateway_weight`：网关优先级和权重。

保存前可点击 `测试连接`。保存或测试后，如果插件支持签到，列表里的 `可签到` 状态会同步更新。

## 浏览器存储导入

部分站点可通过浏览器控制台导出的 localStorage/sessionStorage 快速填充凭证。

入口：`新增/编辑站点 -> 浏览器存储导入`。

支持：

- 粘贴 JSON 对象。
- 粘贴被字符串包裹的 JSON。
- 从 localStorage 中提取 token、refresh token、用户邮箱、User-Agent 等。
- 自动建议插件类型、站点名称和站点地址。

注意：

- 只在本地可信环境使用。
- 导出的 token/cookie 等同账号凭证，不要提交到仓库或分享给他人。

## 分组管理

分组用于两个场景：

- 站点列表筛选和归类。
- 网关请求通过 `?group=<分组>` 只使用某组路由。

站点可归属多个分组。分组管理会维护分组目录，并同步处理站点和路由中的分组名称。

## 签到

### 单站点签到

在 `站点中心` 找到站点，点击操作列中的 `签到`。

如果站点不支持签到，操作列不会显示签到按钮。

### 批量签到

在站点表左侧勾选可签到站点，点击 `签到选中`。

站点的 `可签到` 开关含义：

- `可以`：参与批量签到和定时签到。
- `禁止`：不参与批量签到和定时签到；列表中也不会显示该站点的签到状态。

### 定时签到

进入 `设置` 或站点中心的签到配置入口，设置：

- 定时签到开关。
- 每日运行时间。
- 时区。
- 并发站点数。
- 站点间隔秒数。
- 重试次数。
- 请求超时。
- 是否只执行启用站点。

签到结果可在签到日志或站点列表中查看。

## API Key 和余额

支持的站点可点击：

- `API Key`：查看或同步站点 API Key 列表。
- `余额`：探测站点余额或路由余额。
- `邀请`：读取邀请链接和邀请码，支持复制。

公开邀请码列表显示在登录页，只有已启用且有邀请信息的站点会展示。

## 验证与对话

`验证与对话` 同时承担模型连通性验证和真实对话测试，不再单独提供“模型连通性检测”页面。

流程：

1. 选择已保存站点。
2. 系统读取该站点保存的 API Key、请求 API URL 和路由类型，自动请求模型列表。
3. 在模型下拉框选择模型。
4. 输入消息发送。

请求方式由模型决定：

- 普通模型走 OpenAI 兼容 `/chat/completions`。
- `gpt-image-*`、`dall-e*`、`imagen` 等图片模型走图片生成/编辑接口。
- 图片模型支持预设尺寸和自定义宽高；锁定按钮会以当前宽高作为固定比例，继续修改任一边时自动联动另一边。
- 对话和图片模型都可以添加参考图；实际是否支持由上游模型决定。

如果模型列表加载 404，先检查站点的 `api_request_urls` / `gateway_request_urls` 是否是模型请求根地址，并确认后端已经更新到包含 `/api/tools/models` 的版本。

## 余额与套餐余量

站点状态刷新和路由余额探测会尽量读取真实平台接口：

- `sub2api-platform`：优先读 `/api/v1/subscriptions/progress`，识别日、周、月限额窗口；如果存在日限额，优先展示当日剩余可用额度。失败时再回退 `/api/v1/subscriptions/summary` 或 `/api/v1/keys` 额度字段。
- `yellowpeach-newapi`：优先读 `/api/subscription/self`，再回退 `/api/usage/token/`。
- DeepSeek、StepFun、SiliconFlow、OpenRouter、Novita AI 会按官方余额接口探测。
- `/v1/usage` 仅作为通用 OpenAI 兼容 fallback。

套餐余量字段写入 `package_remaining/package_total/package_used/package_unit/package_display`，用于显示订阅或 Token 套餐余量。`last_balance` 表示当前可用余额或当前限额窗口的剩余额度。

## 聚合网关

### 网关地址

推荐使用：

```text
http://<host>/api/gateway
```

兼容旧路径：

```text
http://<host>/api/gateway/v1
```

无需在客户端里强行追加 `/v1`。系统会把 `/api/gateway` 后面的路径透明转发到上游。

### 认证

所有网关请求使用 Bearer Key：

```http
Authorization: Bearer <GATEWAY_API_KEY>
```

Key 可通过环境变量初始化，也可在后台 `网关中心 -> 网关策略` 中修改。

### OpenAI 风格请求

```bash
curl http://127.0.0.1:8972/api/gateway/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

### 按分组路由

```bash
curl "http://127.0.0.1:8972/api/gateway/chat/completions?group=main" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"ping"}]}'
```

### 路由类型

支持类型：

- `claude`
- `codex`，也表示 GPT/OpenAI 兼容路由
- `gemini`

可以手动指定：

```text
?type=claude
```

也可以不传 `type`。系统会根据请求体中的 `model` 自动选择 Claude、GPT/Codex 或 Gemini 路由。

## 网关路由池

进入 `网关中心`。

常见操作：

- `同步路由`：从站点凭证和 API Key 列表生成路由。
- `测试`：测试单条路由模型接口是否可用。
- `余额`：探测该路由关联站点余额。
- `历史`：查看该路由的请求历史。
- `熔断重置`：将打开的熔断恢复为可探测状态。
- `启用/停用`：控制路由是否参与网关调度。
- `类型`：手动指定 Claude/GPT/Gemini 路由类型。

路由列表只展示关键字段，出口、快照、回退地址等细节通过提示或详情查看。

## 网关策略

策略在 `网关中心 -> 网关策略` 配置。

### 主策略

| 策略 | 适用场景 |
|---|---|
| Smart 评分 | 综合延迟、并发、失败次数、优先级做选择，适合多数生产场景 |
| Round Robin | 均匀轮询，适合路由质量接近时分摊请求 |
| Latency First | 优先低延迟路由，适合追求响应速度 |
| Priority | 严格按 `priority` 数值升序选择路由，适合主备或成本分层 |

`Priority` 策略下，数值越小优先级越高。只要高优先级路由未达到单路由并发上限，网关会继续使用该路由；延迟、权重、当前并发均衡和近期失败降权不会把流量提前分配给低优先级路由。

### 并发控制

网关策略中可配置单路由并发上限、并发转移策略和并发溢出优先级：

- 单路由并发上限：单条路由达到上限后，新请求转到其它未满路由。
- 并发达上限转移：保持当前主策略排序，只在达到上限后转移。
- 并发均衡转移：非 `Priority` 主策略下，优先选择当前并发更低的未满路由。
- 并发溢出优先级：所有候选路由都达到上限后参与排序，支持低延迟优先或按顺序优先。

### 熔断

路由连续失败达到阈值后会进入 `open` 状态，在冷却时间内不参与调度。冷却结束后进入 `half_open`，允许一次探测；成功恢复，失败继续熔断。

## 监控和消耗

网关中心包含：

- `24h 概览`：请求数、成功率、延迟、流式成功率等。
- `实时调用`：当前正在执行的网关请求。
- `时间段消耗`：按时间范围查询请求数、成功率、Token 使用量、官方估算费用，并列出使用过的路由。
- `路由历史`：每个路由的最近请求列表。
- `最近请求`：全局最近网关请求。

日志中常见字段：

- 状态码。
- 成功/失败。
- 延迟。
- 策略。
- 路由标签。
- 失败原因。
- 是否流式。
- Prompt / Cached / Completion / Total Token。
- 上游费用和官方估算费用。

## 常见问题

### 登录后提示无权限或状态失效

可能原因：

- `SECRET_KEY` 变更导致旧 token 失效。
- 浏览器保存了旧 token。

处理：重新登录，必要时清理浏览器 localStorage。

### 前端打不开，提示 frontend/dist 不存在

生产模式下后端直接服务 `frontend/dist`。先构建前端：

```bash
cd frontend
npm ci
npm run build
cd ..
./start-prod.sh
```

开发模式建议直接用：

```bash
./run.sh
```

### 网关返回 401

检查：

- `Authorization: Bearer <key>` 是否正确。
- 后台 `网关策略` 中的 API Key 是否与客户端一致。
- 环境变量 `GATEWAY_API_KEY` 是否只在首次初始化时生效，后续已被数据库设置覆盖。

### 网关提示没有可用路由

检查：

1. 站点是否启用。
2. 站点是否有 API Key。
3. 路由是否同步。
4. 路由类型是否与请求 `type` 或 `model` 匹配。
5. 分组筛选是否过窄。
6. 路由是否被停用或处于熔断状态。

### 签到状态不显示

如果站点被设置为 `禁止` 签到，列表不会显示签到状态。这是预期行为，表示该站点不参与签到任务。

### API Key 同步不到

不同站点接口结构差异较大。可尝试：

- 确认登录凭证有效。
- 先执行 `测试连接`。
- 检查插件类型是否正确。
- 对通用 HTTP 插件配置正确的状态接口路径和字段路径。

### 流式请求不流畅

如果前面有反向代理，确认关闭响应缓冲，例如 Nginx 设置：

```nginx
proxy_buffering off;
proxy_read_timeout 600s;
```

## 数据安全

- 不要把 Cookie、access token、refresh token、API Key、数据库、浏览器存储导出内容提交到 Git。
- 公开部署时务必使用 HTTPS。
- 定期备份 SQLite 数据库。
- API Key 泄露后应立即在上游站点和本系统中轮换。
